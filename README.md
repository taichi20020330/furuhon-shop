# 浮かぶ古本屋

本の写真がふわふわ浮かぶ空間を歩いて選ぶ、決済なしの古本ショップです。
お客さんが本を選んで申し込むと、店主（pinoko72447@gmail.com）にメールが届きます。受け渡しと支払いは店主宅で現金です。

```
├── index.html                … サイト本体
├── data/books.csv            … 本のデータベース（Excel・Numbers・Googleスプレッドシートで編集）
├── images/                   … 背景透過した本の写真（<id>-front.webp / <id>-back.webp）
├── inbox/                    … ここに撮った写真を入れる（GitHubには上がりません）
├── 写真を処理する.command     … Mac：ダブルクリックで inbox の写真を一括処理
├── 写真を処理する.bat         … Windows：同上
├── tools/process_photos.py   … 一括処理の本体
└── apps-script/Code.gs       … 注文メールを送る仕組み（Googleに置く）
```

## いつもの流れ（本を追加するとき）

1. **撮る**：本を1冊ずつ、真上から「表 → 裏」の順で撮る。机の上で撮れば十分です。
2. **入れる**：写真を全部 `inbox/` に入れる（iPhoneのHEICのままでOK）。
3. **処理する**：`写真を処理する.command`（Windowsは `.bat`）をダブルクリック。
   - 背景を消して、本の傾きや台形のゆがみをまっすぐに直します
   - 裏表紙のバーコードを読み、書名・著者・出版社・カテゴリを自動で調べて `data/books.csv` に追加します
   - バーコードがある方を自動で「裏」とみなすので、撮る順番が多少前後しても大丈夫です
   - 処理が終わった元写真は `inbox/_done/`、失敗したものは `inbox/_failed/` に移ります
4. **値段を入れる**：`data/books.csv` を開いて `price` を入れる。`category` が空なら入れる。
   **値段が空の本はサイトに出ません**（＝準備中の状態にしておけます）。
5. **公開する**：GitHub に上げる（下の「更新のしかた」）。

初回だけ、セットアップで1〜2分かかります（Python 3.10 以上が必要。Macは `python3 --version` で確認できます）。

### うまくいかないとき
- バーコードが読めなかった本は書名が空欄になります。CSVに手で入れてください。
- 切り抜きはAIを使わない自前の処理です（`tools/book_cutout.py`）。「本は長方形」「本らしい縦横比」「縦向き」を前提に、本の四隅を探します。写真は回転しません。
- 本が見つからない写真も失敗にはせず、写真をそのまま使って登録し、最後の「確認が必要な本」に出します。
- 本と机の色が近いとき（白い本を白い机に置くなど）は、濃い色の布や紙の上で撮ると確実です。

### 切り抜きをやり直す・確かめる
- **全部作り直す**：`写真を作り直す.command` をダブルクリック（ターミナルなら `.venv/bin/python tools/process_photos.py --redo`）
  `inbox/_done` と `inbox/_failed` の写真も含めて切り抜き直します。CSVの書名・値段などはそのまま残ります。
- **どこを本と判断したか見る**：`.venv/bin/python tools/process_photos.py --check`
  元写真に緑の枠を描いた画像が `inbox/_check/` にできます（CSVや画像は変わりません）。

## データベース（data/books.csv）

| 列 | 内容 |
|---|---|
| `id` | 本ごとの記号。ISBNが読めたらISBN、同じ本が2冊目なら `-2` が付きます。注文メールにも載るので箱詰めの照合に使えます |
| `isbn` `title` `author` `publisher` `label` | 書誌情報（`label` は「岩波新書 1002」などのシリーズ名） |
| `category` | 空間の中で同じカテゴリの本が一つの島にまとまります。自由に名前を付けてOK |
| `format` | `shinsho`（新書）/ `bunko`（文庫）/ `tanko`（単行本）。写真がない本の大きさに使います |
| `price` | 値段（数字だけ）。**空ならサイトに出ません** |
| `condition` | 状態のひとこと（裏返したときに表示） |
| `sold` | 売れたら `1`。「売約済」の印が付いて選べなくなります |
| `front` `back` | 写真のパス（ツールが自動で入れます） |
| `sample` | `1` は見本データの印。**`sample` が 1 の行は見本なので、在庫が揃ったら行ごと消してください** |

保存は **CSV UTF-8** 形式で（Excelなら「名前を付けて保存 → CSV UTF-8（コンマ区切り）」）。

## 注文メールの設定（Google Apps Script・無料、最初に一度だけ）

1. pinoko72447@gmail.com のアカウントで https://script.google.com を開き「新しいプロジェクト」
2. 中身を全部消して、`apps-script/Code.gs` の内容を貼り付けて保存
3. 上の関数選択で `testMail` を選んで「実行」→ 許可を求められるので許可（テストメールが届けばOK）
4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分** ／ アクセスできるユーザー：**全員**
5. 表示された「ウェブアプリのURL」をコピーして、`index.html` 上部の `orderEndpoint: ""` に貼り付ける

`orderEndpoint` が空のあいだは、申し込むと「届くメールの文面」が画面に出るだけです（動作確認用）。

## 公開（GitHub Pages・無料）

リポジトリの Settings → Pages → Branch を `main` / `(root)` にして Save。
数分後に `https://taichi20020330.github.io/furuhon-shop/` で公開されます。

### 更新のしかた
GitHub Desktop を使うのがいちばん楽です。写真処理とCSV編集のあと、「Commit」→「Push」を押すだけで、数分でサイトに反映されます。

### 手元で確認する
`index.html` をダブルクリックで開くと、ブラウザの制限でCSVが読めません。リポジトリのフォルダで
`python3 -m http.server` を実行し、ブラウザで http://localhost:8000 を開いてください。

## 知っておくとよいこと
- 在庫は自動では減りません。注文メールが来たら、その本の `sold` を `1` にして更新してください。
- 送信結果はブラウザ側では確認できない仕組みです（Apps Script の制約）。届いたメールを基準にしてください。
- お客さんの名前・連絡先はメールにしか残りません。サイトやGitHubには保存されません。
- 元写真（inbox）はGitHubに上がらない設定です。
